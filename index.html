QUICK GUIDE
#

1. Hash

A hash is a digital fingerprint calculated from data. SHA-256 produces a 256-bit digest, usually shown as 64 hexadecimal characters.

Certificate data → SHA-256 → 64-character hash
⬡

2. Block

A block groups data together with metadata such as its timestamp, nonce and hash of the previous block.

Block = data + previous hash + nonce
⛓

3. Chain

Each block stores the previous block's hash. This linking makes changes to old data detectable when the chain is validated.

Block 3 → Block 2 hash → Block 1 hash
⚒

4. Proof of Work

Mining repeatedly changes a nonce until the block hash meets a difficulty rule. More leading zeros generally mean more attempts.

Hash starts with “00” → puzzle solved
✓

5. Verification

CertiChain looks up the certificate ID, recalculates its hash and checks block links. A mismatch indicates a problem with the stored data.

Stored record = expected record?
◎

6. Decentralization

A public blockchain is maintained by multiple participants. This project runs locally in one browser and does not implement a distributed network.

Quick viva questions

Why do we use blockchain for certificates?

It can provide a traceable, tamper-evident record that helps verifiers detect changes to certificate data.

What is SHA-256?

It is a cryptographic hash function that maps input data to a 256-bit digest.

What is a nonce?

A number changed during mining to search for a hash that meets the difficulty target.

What happens if someone changes a certificate record?

The recalculated hash may no longer match the stored hash, and the chain's links may fail validation.

Is this connected to a real blockchain?

No. It is a browser-based educational simulation. A real deployment would need a blockchain network, trusted issuer identities and appropriate security controls.

Does Proof of Work prove a certificate is genuine?

No. Proof of Work solves a computational puzzle. Certificate authenticity depends on trusted issuance and verification of the record.
